# 花边寻纹

上传一张蕾丝花边，在云端样品库里找出花纹最接近的布料。检索输入完整保留，样本库建索引时排除顶部文字；比对局部花纹和位置关系。

公开网址：<https://zazail.github.io/lace-pattern-search/>

管理页面：<https://zazail.github.io/lace-pattern-search/admin.html>

样品图片和索引都在 GitHub 仓库 `zazaIl/lace-pattern-search` 里。打开网页就能检索，不需要登录，也不需要安装软件。

## 检索

1. 打开公开网址。
2. 把 JPG 或 PNG 拖进上传区，或点击「选择图片」。一次检索一张。
3. 输入图片完整保留，无需手动裁剪。样本库上传和重建索引时自动识别并排除顶部文字，不修改保存的原图。
4. 点击「寻找相似花纹」。固定展示 Top 10（不足 10 件则全部展示），每张包含缩略图、相似度和品名编号，不因低分隐藏。
5. 低分候选标记为「证据不足，待核对」，不会因为进入 Top 10 被标成同款。
6. 点击缩略图可以看大图。

样品库刚更新时，公开页面可能要一两分钟才看得到新图。可以点「刷新样品库」。

## 管理样品

管理页只给你自己用。访问令牌保存在这台浏览器里，不会写进网站代码。

### 创建令牌

1. 用 zazaIl 账号登录 GitHub。
2. 打开 Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
3. Repository access 只选择 `lace-pattern-search`。
4. Permissions 里把 Contents 设为 Read and write。
5. 生成后复制令牌，粘贴到管理页，点击「验证连接」。

也可以使用经典令牌，勾选 `repo` 权限。

### 上传

1. 连接成功后，把 JPG 或 PNG 拖进上传区，或一次选择多张。
2. 品名编号默认取文件名，写入前可以改。
3. 点击「写入样品库」。页面会先计算纹理索引，再把缩小后的图片和索引一起提交到云端。
4. 一次最多 40 张。样品很多时请分批上传。
5. 上传前会把长边限制在 960 像素，透明背景会补成白色。

### 修改编号和删除

1. 在「全部样品」里按编号筛选。
2. 改完编号后点击「保存编号修改」。
3. 点击「删除」并确认后，图片和索引会一起从云端移除。
4. 以后如果更新了比对算法，点击「重新计算全部索引」。它会按云端现有图片重算，不需要重新选文件。

## 更新网站代码

在项目目录里改完代码后：

```bash
git add -A
git commit -m "更新花边寻纹"
git push origin main
```

`main` 分支配置了 GitHub Pages，推送后会自动发布。大约一两分钟后刷新公开网址即可。

不要把访问令牌写进文件，也不要提交 `.env` 一类的密钥。

本地预览：

```bash
python3 -m http.server 8080
```

浏览器打开 <http://localhost:8080>。用文件协议直接双击 `index.html` 时，浏览器会拦截样品库读取。

## 比对方式

算法版本 5：先在每张图内部归一化 RGB 亮度，并沿主要色差方向生成花纹结构图；不同图片之间不比较颜色值。黑白图片使用亮度特征。增加 CLAHE 局部对比度归一化，减少阴影和不同底色造成的细节强弱差异；轻度平滑降低网眼和纱线噪声，随后提取多尺度 ORB 局部特征，并保存正、反两种明暗极性。

颜色变化很小的中性布料使用灰度结构；灰度与色差结构之间连续过渡，避免重新压缩引入微小色彩噪声后突然切换表示方式。文字区识别也接受偏黄、偏灰的卡纸。s025、s055、s036 的重新压缩回归覆盖这些情况。

预处理按用途区分：检索输入始终保留完整画面，上传入库和重建样本索引才排除文字头部。卡纸颜色由顶部区域估计，结合横向分隔线识别品牌、品号和电话文字，保存的样本图片仍保持完整。如果输入也是样品卡，必须检测到实际分隔线才排除标签对局部特征和归一化参数的干扰，避免彩色商标改变浅色布料的结构表示、占用花纹特征点；局部特征坐标还原到完整输入画面。普通照片不因上方有浅色背景而丢掉顶端花纹。相同标签、不同花纹，以及完整输入匹配去除标签的库图，都有专门回归测试。

新增 RootSIFT 尺度空间特征：查询同时提取原尺度与半尺度，描述子支持镜像和明暗反转，能在圆形裁片、单个放大花朵和稀疏曲线中寻找局部对应，不要求照片包含完整重复周期。先用可复用 KD forest 检索全库描述子，再对最多 24 个、且票数达到领先候选 8% 的候选验证几何关系；强证据候选不重复做 ORB 验证。前 6 个高票弱候选另做成对描述子验证，减少相近花纹互相竞争造成的漏检。RootSIFT 验证要求至少 8 个独立对应点、至少 25% 的有效比例、双侧空间覆盖和合理的投影关系；相邻重复方向点不重复计数。

保留 ORB 分支作为补充，比较整图和竖向二分、三分区域。半幅与三分之一幅各取左、中、右位置，保留重叠区域以免花朵刚好跨越切线。特征坐标保持在原图内，每个区域独立进行匹配和几何验证，不要求两个完整画面处于同一个重复周期。

重复花纹可能让最近的两个描述子对应同一花朵的不同重复单元，原来的全局比例检验会误删这些正确点。现在保留最近的八个候选，在各区域内部重新做比例检验；每个样品点仍只接受一个对应。RANSAC 校验要求足够多的点在两图中都有空间覆盖，局部区域至少 12 个有效对应点且有效比例至少 25%，防止截取小网眼导致误匹配。几何证据直接决定分数，不再对已确认候选执行耗时的纹理穷举。旧纹理字段保留用于兼容已有数据和诊断。

未通过几何验证的候选，根据局部描述子外观给出最高 20% 的结构参考分，用来排列 Top 10 中的弱候选，避免全部同为零分而按库内顺序展示。参考分不参与已验证花纹的评分，也不会被标记为同款或强匹配；空白图仍为零分。

界面百分比表示匹配证据强度，不是“同款概率”。算法和索引必须一同更新；仓库已包含 90 张样品的版本 5 索引。旧索引可在管理页「重新计算索引」，升级时不会丢弃原样品记录。识别在用户浏览器内完成，OpenCV 4.13.0 与小型 VLFeat WebAssembly 运行时随网站分发，不需要服务端或外部识别 API。

## 算法回归测试

```bash
npm install
npx playwright install chromium
npm test
```

`npm run rebuild:index` 用网站的实际浏览器预处理流程重新计算所有样品，验证后才保存索引。测试包含用户提供的四组样品卡和实拍图（s067、s060、s003、s015）、全部样品重新上传后检索自身、两组实拍对全部其他样品的误匹配、局部裁切、旋转、灰度变体、新实拍左半幅/右半幅/中间三分之一幅、空白图，以及哈希平移方向。库内不同花纹也进行两两检索；人工查看后，s008/s009、s012/s013、s016/s017、s019/s020、s021/s022、s032/s033、s062/s063、s065/s066、s086/s087 被标记为有效的近似花纹组，不将这九组的相似结果误计为负例。它们具有相同或近似的花型轮廓；例如 s012/s013 标注 91208/91208-1，s008/s009 标注 91205，s062/s063 标注 91250，s016/s017 标注 91211/91211-1，s086/s087 标注 91272，颜色、宽度、纱线或光泽可以不同。测试报告位于 `scripts/tmp/library-results.json`。新增圆形与稀疏实拍的实际上传界面回归：s003 要求进入前 2 且有几何证据，s015 要求第 1；除圆形图另一个相近花型 s025 外，其余候选必须低于 50%。s003（91200）与 s025（91215）品号不同、花朵布局接近，不能仅凭局部照片断言是同款，也没有在生产代码中为这两个 ID 设置特殊规则。

界面测试确认固定 Top 10、每项相似度、旧浏览器阈值不再过滤结果、四组正确样品排序和手机布局。这些测试覆盖现有样品，新增实拍场景仍应继续扩充回归图片。

本机 v5 回归结果：90/90 库图重新上传后自身排第 1；排除上面人工确认的近似组后，其他花型最高分为 19.6%。圆形实拍的目标 s003 排第 2、62.9%，s025 排第 1、67.1%；稀疏实拍 s015 排第 1、55.8%。前两组实拍仍排第 1。相同浏览器中，四组实拍的 v4 → v5 总耗时依次约为 15.8 → 4.6 秒、8.6 → 1.3 秒、4.9 → 4.8 秒、4.5 → 2.3 秒；第一张 v5 查询包含建立 KD 索引的开销，其余复用索引。这是本机现有样本的测量，不代表未知图片或其他设备的保证。

开发者可用 `LACE_BROWSER` 指定 Chromium/Edge 可执行文件；`LACE_NODE_MODULES` 可指定预装依赖目录。用户打开网站检索时无需安装这些测试依赖。

## 限制

- 只支持 JPG、PNG，单张原始文件不超过 20MB。
- 免费 GitHub 仓库建议保持在 1GB 以内。页面会先缩小再保存，大约 500 张样品通常足够。
- 仓库必须是 Public，免费的 GitHub Pages 才能公开访问。
- 严重褶皱、模糊、线材与底色难以分离，或截取得太小以至于看不出完整花纹时，匹配证据会下降。Top 10 始终保留，但低分候选需要人工核对。

底层模块来源、许可证与可复现编译命令见 [native/README.md](native/README.md)。
